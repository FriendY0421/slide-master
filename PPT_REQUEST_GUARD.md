# PPT Request Guard — Mandatory New-Deck Entry Gate

This file is the fail-closed authority for every **new presentation deck** request.

## Canonical entry routing

For every FriendY new PPT/presentation/slides request:

1. Bind first to project `SLIDE_MASTER` and repository `FriendY0421/slide-master`.
2. A host-required `artifact_handoff` / presentation-preparation call may occur first because the ChatGPT host requires it, but that call is **preparation only**. It is not template selection, not FAH `ALLOW`, and never permission to create a PPTX.
3. Evaluate the FAH Execution Contract before research, project initialization, SVG authoring, or PPTX export.
4. Missing `TEMPLATE_SELECTION` evidence is `WAIT_USER_ACTION` and must stop generation.
5. Upstream `byungjunjang/slide-master`, generic slide generators, host-native artifact shortcuts, or a successful `artifact_handoff` call must not bypass this gate.

**Hard interpretation:** `artifact_handoff = prepare`; valid `template_selection.json = permission to generate`.

## Scalable live template catalog — never hard-code ids or counts

Template discovery is **GitHub-index-driven** from the latest `FriendY0421/slide-master` `main` state.

Canonical catalog sources:

- `.claude/skills/ppt-master/templates/decks/decks_index.json`
- `.claude/skills/ppt-master/templates/layouts/layouts_index.json`
- unified by `.claude/skills/ppt-master/scripts/template_catalog.py`
- conversation manifest generated by `.claude/skills/ppt-master/scripts/template_gallery_chat_manifest_v2.py`
- self-contained HTML fallback generated by `.claude/skills/ppt-master/scripts/template_gallery_inline_html.py`
- stable visual catalog generated by `.claude/skills/ppt-master/scripts/template_gallery_markdown.py`

Adding, updating, or removing a registered Deck/Layout must be reflected by the live indexes so the next recommendation automatically changes.

Selection keys are collision-safe:

- `deck:<id>`
- `layout:<id>`
- `free`

Existing bare Deck ids remain backward-compatible only when unambiguous.

## Canonical template-selection surface — CONVERSATION INTERACTIVE PICKER FIRST

For ChatGPT/GPTS conversational hosts, the first-choice selection surface is a **conversation-native interactive picker** such as App Block / GenUI when that capability is available in the current host.

A new-PPT request must not emit a plain template recommendation list first when the interactive picker capability is available.

Required flow:

1. Read the latest live Deck/Layout catalog.
2. Rank genuinely relevant templates for the actual request; recommendation never auto-selects.
3. Render 5–10 real registered candidates when available (default target 6, up to 10) in the conversation-native interactive picker.
4. Allow card/page navigation and open the selected candidate's detail view.
5. Show up to 6 real registered layouts/examples from the exact workspace.
6. Offer Free Design separately.
7. If useful, show 3–5 presentation-production presets in the same interaction pattern.
8. Show the final selection token, e.g. `deck:mckinsey | preset:storytelling_proposal`.
9. The user returns/explicitly confirms the final template id in chat.
10. Only then record template evidence and start generation.

### Primary UI contract

When App Block / GenUI is available, the picker must provide:

- recommendation cards and access to the complete current catalog;
- real registered representative previews;
- card click/tap to detail view;
- previous/next or equivalent navigation;
- up to 6 exact registered detail previews;
- a visible selected state;
- `다른 템플릿 보기` or equivalent return control;
- `이 템플릿 선택` or equivalent final UI action;
- Free Design;
- responsive desktop/mobile behavior;
- no hover-only essential controls.

The interaction pattern follows the user-approved gallery concept represented by `template_gallery_inline_html.py`, but the primary surface is the **in-conversation interactive UI**, not an external link.

## Picker render evidence

For newly recommended-template flows, selection evidence must carry picker-surface evidence.

Use:

`picker_surface_gate.py record <picker.json> --surface <surface> --purpose "<purpose>" --source-ref "github:main" --candidate-count <n> --detail-preview-max 6 --rendered`

Valid surfaces:

- `app_block`
- `genui`
- `conversation_native_visual`
- `inline_html`
- `github_visual_catalog`
- `text_last_resort`

`app_block` / `genui` are the preferred primary surfaces. Any lower-priority surface requires a concrete `--fallback-reason`. `text_last_resort` is valid only when no visual surface is available and must never be described as a visual gallery.

When the user directly names a registered template before recommendation, picker rendering is not required; record the choice with the direct-template path.

## Selection evidence and generation permission

A preview view, card click, recommendation, `artifact_handoff` call, or tentative choice is not final selection.

Recommended-template flow:

`record_template_choice_v2.py <deck:id|layout:id|free> --confirmed --purpose "<purpose>" --picker-evidence <picker.json> --output <result.json>`

Direct user-specified registered template flow:

`record_template_choice_v2.py <deck:id|layout:id|free> --confirmed --purpose "<purpose>" --direct-template --output <result.json>`

Then initialize only through:

`new_deck_init.py <project_name> --template-selection-result <result.json>`

Only after this evidence exists may content research/generation begin.

## Fallback hierarchy

Use this exact order:

1. **Primary:** conversation-native interactive App Block / GenUI on a host that actually supports the app.
2. **Automatic host-rejection fallback:** when the real tool call returns `FORBIDDEN` / `does not support developer MCPs` and Remote Desktop Commander is available, run `ops/windows/Open_SlideMasterPicker_Fallback.bat <purpose>` and open the self-contained GitHub-backed HTML picker.
3. **Secondary:** another conversation-native real-preview visual/card surface when available.
4. **Recovery:** stable GitHub-rendered visual catalog (`docs/template-gallery/README.md`).
5. **Last resort:** text-only IDs, with explicit visual-unavailable explanation and recorded fallback reason.

`FORBIDDEN` / developer-MCP host rejection is a product-surface classification. Do not restart CSP, preview-image, port-3000, or Tunnel debugging for the same exact rejection unless separate runtime evidence changed. A lower-priority path still requires explicit user selection and picker evidence.

## Fail-closed UI and execution rules

The following are explicit failures and must stop the new-deck pipeline:

- generating PPTX immediately after `artifact_handoff`;
- inventing template names, IDs, screenshots, or previews;
- using a fixed/hard-coded template list that ignores the current GitHub indexes;
- listing template names/IDs in prose when an App Block / GenUI picker is available;
- claiming a gallery, modal, image, or picker was displayed when the current turn did not visibly render it;
- saying `Picker를 열었습니다` after a `FORBIDDEN` / developer-MCP host rejection instead of switching to the documented fallback;
- recording a recommended-template selection without valid picker evidence;
- using a lower-priority picker without a fallback reason;
- recording selection before the user explicitly returns a final id;
- creating/researching the deck while the user is still choosing;
- silently defaulting to Free Design;
- treating picker failure as permission to skip template selection.

## Required visible behavior

The selection surface must provide:

1. Current registered Deck/Layout templates, not a fixed historical list.
2. Purpose-aware 5–10 candidate recommendations when enough suitable templates exist.
3. A real representative preview for every offered visual candidate.
4. Up to 6 real registered detail layouts/examples for the tentative choice.
5. Collision-safe selection IDs.
6. Free Design as an explicit option.
7. No redrawn approximations presented as registered templates.
8. A clear final-selection/confirmation step.

## Fail-closed evidence

No valid `template_selection.json` (selected or documented exemption) means the new-deck gate did not pass. New gate-version records for recommended-template flows also require valid picker evidence. `picker_surface_gate.py`, `record_template_choice_v2.py`, `template_gate.py`, `new_deck_init.py`, and guarded `svg_to_pptx.py` form the downstream enforcement layer.
