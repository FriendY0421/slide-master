이 요청은 slide-master 풀 파이프라인의 독립 cold-run 벤치마크 실행이다.

당신은 이 실행의 유일한 최상위 main agent다. 하위 에이전트나 별도 에이전트 세션에 어떤 작업도 위임하지 말고, 특히 SVG 저작은 반드시 직접 한 장씩 순차 수행하라. superpowers 플러그인은 사용하지 마라. 웹 검색도 하지 마라. 사용자의 고정 승인값이 이 프롬프트에 이미 포함되어 있으므로 추가 질문이나 확인을 기다리지 말고, 실패가 없으면 최종 검증까지 연속 실행하라.

## 1. 실행 설정과 격리 확인

가장 먼저 현재 작업 루트의 `projects/.cold_ab/arm_config.json`을 읽고 그 값만 이 실행의 arm 설정으로 사용한다. 이어서 아래를 확인한다.

1. 현재 작업 디렉터리의 절대경로가 config의 `worktree`와 같다.
2. `git rev-parse HEAD`가 `expected_head`와 정확히 같다.
3. `git status --porcelain`이 비어 있다.
4. config의 `project_path`가 존재하지 않는다.
5. `private_source`와 `immutable_fixture`의 SHA-256이 모두 `fixture_sha256`과 같다.
6. 두 observer 스크립트의 SHA-256이 config의 고정 hash와 같다.

하나라도 실패하면 삭제, reset, checkout, 복구를 시도하지 말고 즉시 중단해 정확한 원인을 보고하라.

이 실행은 새 `codex exec --ephemeral` 세션과 새 detached worktree, 새 프로젝트를 사용한다. 다음 항목은 절대로 열거나 검색하거나 복사하지 마라.

- 현재 작업 루트 밖의 다른 `slide-master` worktree, 기존 evidence, 기존 프로젝트
- 다른 실행의 `design_spec.md`, `spec_lock.md`, `execution_plan.json`
- 기존 SVG, text-fit JSON, recommendations/result JSON, PPTX, 실행 로그
- speed/round/A-B 결과 문서와 과거 벤치 결과
- 사용자 메모리 폴더

허용된 외부 기존 파일은 config가 지정한 `immutable_fixture` 하나뿐이다. 실제 import에는 현재 worktree 안의 `private_source`만 사용하며, 기존 산출물은 어떤 형태로도 재사용하지 않는다.

## 2. 라우팅과 owner 로드

루트 `AGENTS.md`와 `CLAUDE.md`를 읽고, 전체 프레젠테이션 owner보다 먼저 `.claude/skills/ppt-master/workflows/routing.md`를 EOF까지 읽어 route를 결정한다. 입력은 Markdown source에서 새로운 PPT를 만드는 main SVG route다. 선택된 canonical owner `.claude/skills/ppt-master/SKILL.md`를 처음부터 EOF까지 완전히 읽는다. 출력이 잘리면 작은 구간으로 나눠 끝까지 읽는다. 이후에는 owner가 현재 단계에서 요구하는 참조만 읽고 경쟁 route의 full owner는 읽지 않는다.

checkout에 존재하는 계약을 그대로 수행한다. 다른 arm의 동작을 추측하거나 흉내 내지 말고, checkout에 없는 packet이나 fast path를 임의로 만들지 않는다.

## 3. 프로젝트 생성, telemetry, source import

필수 route/owner preload가 끝나면 바로 canonical `project_manager.py init`으로 config의 `project_name`을 `ppt169` 형식으로 생성한다. 실제 생성 경로가 config의 `project_path`와 일치하는지 확인한다.

프로젝트 init 직후 config의 `observer_run_telemetry`를 사용해 telemetry를 시작한다. 인수는 다음 의미를 정확히 따른다.

- project: config `project_path`
- run id: config `run_id`
- repo root: 현재 worktree
- fixture: config `immutable_fixture`
- fixture id: `learning-source-v1`
- route: `main-svg-flat-text`
- cache condition: `cold`

여기서 cold는 독립 ephemeral agent context, 새 process, 새 worktree, 빈 project, 산출물 무재사용을 뜻한다. OS page cache와 서버측 prompt cache는 강제 초기화하지 않았다는 제한을 최종 보고에 명시한다.

그 다음 canonical `project_manager.py import-sources`에 config의 `private_source`를 주고 owner 계약대로 `--move`하여 import한다. `immutable_fixture`는 절대로 이동하거나 수정하지 않는다. source import 뒤 canonical preflight를 실행하고 FAIL을 해결한다. 이미지가 없으므로 `--needs-images`는 사용하지 않는다.

## 4. 고정 Strategist 승인

source와 owner가 요구하는 Strategist 참조/template을 읽어 recommendations를 이 프로젝트에서 새로 작성한다. 선택 기본값은 아래 고정 payload와 정확히 일치시킨다. Confirm UI가 요구하는 실제 후보 구조를 제공하되, palette 후보는 최소 3개, Pretendard는 install-local lock의 honest-shortfall 규칙에 따라 단일 고정 후보로 작성한다.

이 테스트에 한해 사용자는 아래 payload를 실제 Confirm UI의 `/api/confirm` endpoint로 자동 제출하는 것을 명시적으로 승인했다. `result.json`을 직접 작성해서는 안 된다. 프로젝트의 `confirm_ui/auto_approval_payload.json`은 `apply_patch`로 새로 작성한다.

```json
{
  "canvas": "ppt169",
  "page_count": "8",
  "audience": "학습 효율을 높이고 싶은 대학생·직장인",
  "content_divergence": "출처의 다섯 학습 전략과 근거는 유지하고 각 전략을 한 장씩 다루는 8장 실천형 서사로 재구성",
  "mode": "narrative",
  "visual_style": "editorial",
  "template": "free",
  "color": {
    "name": "Warm Editorial Focus",
    "palette": {
      "background": "#F6F1E8",
      "secondary_bg": "#E9E1D5",
      "primary": "#1F2A37",
      "accent": "#2563EB",
      "secondary_accent": "#F59E0B",
      "body_text": "#243041"
    }
  },
  "icons": "tabler-outline",
  "typography": {
    "name": "Pretendard Lock",
    "heading": {"cjk": "Pretendard", "latin": "Pretendard", "css": "'Pretendard', 'Malgun Gothic', sans-serif"},
    "body": {"cjk": "Pretendard", "latin": "Pretendard", "css": "'Pretendard', 'Malgun Gothic', sans-serif"},
    "body_size": 24,
    "body_size_unit": "px",
    "sizes": {"title": 48, "subtitle": 32, "annotation": 18}
  },
  "delivery_purpose": "balanced",
  "formula_policy": "text-only",
  "image_usage": ["none"],
  "generation_mode": "continuous",
  "refine_spec": false,
  "stage": "final"
}
```

키 정렬·공백 제거·UTF-8의 semantic canonical JSON SHA-256이 config의 `payload_canonical_sha256`과 같은지 검증한다. recommendations 준비 후 telemetry `confirm/ready`를 기록한다. 실제 Confirm UI를 `--daemon`으로 시작하고 launcher가 출력한 실제 포트를 사용한다. 5050을 하드코딩하지 않는다. UI 문서와 lock 정보를 따라 위 payload를 `/api/confirm`에 POST한다.

생성된 `result.json`에서 `status == confirmed`, `stage == final`, `confirmed_at` 존재, 나머지 payload 필드의 의미적 동일성을 검증한다. 이후 Confirm UI를 canonical `--shutdown`으로 종료하고 telemetry `confirm/complete --outcome ok`, `spec/start`를 기록한다.

## 5. 고정 콘텐츠 범위와 spec

확정 source와 result만 사용해 `design_spec.md`와 `spec_lock.md`를 이 세션에서 처음부터 작성한다. 정확히 8장으로 다음 범위를 따른다.

1. 표지: 효과적인 학습 기술의 핵심 문제 제기
2. 익숙함의 착각과 수동적 재독의 한계
3. 능동적 인출
4. 분산 학습
5. 교차 학습
6. 정교화
7. 이중 부호화
8. 다섯 전략을 실행으로 옮기는 마무리

각 전략은 한 장씩 다루고, 한 페이지에 다섯 전략을 다시 모은 구조적 목록은 만들지 않는다. source 밖의 사실은 추가하지 않는다. 이미지, data chart, table, diagram/visualization template, 발표자 노트, narration은 계획하지 않는다. editorial/narrative, free design, flat PPTX structure, Pretendard, 확정 palette를 따른다. 단순 타이포그래피·기본 SVG shape 기반 에디토리얼 구성은 허용한다.

두 파일을 작성한 직후 checkout의 canonical `validate_spec.py`를 실행하고 모든 오류를 수정한다. checkout이 execution packet을 emit하면 그 사실과 크기를 기록하고, emit하지 않으면 임의 생성하지 않는다. 통과 후 telemetry `spec/complete --outcome ok`를 기록한다. 이미지 단계는 실제로 생략하고 `images/submit --outcome skipped`, `images/complete --outcome skipped`를 각각 기록한다.

## 6. Executor와 저작

checkout owner의 초기 planning-artifact branch와 reference load 계약을 정확히 따른다. 실제로 읽은 초기 planning artifact와 Executor reference의 경로·개별 byte를 최종 보고용으로 기록한다. packet 경로라면 packet만 세지 말고 owner가 즉시 요구하는 `spec_lock.md` 재독도 반드시 포함한다. 읽기 횟수·token이 실제로 계측되지 않으면 추정값을 metrics에 쓰지 않는다.

telemetry `executor/start`를 기록하고 owner가 요구하는 live preview를 실제로 시작한다. 실제 URL을 기록한다. 고정 design parameters를 보고한 뒤 SVG 8장을 main agent가 한 장씩 순차 작성한다.

- SVG batch 생성 script, template loop, 기존 페이지 copy 금지
- 여러 SVG를 한 patch에 묶는 것 금지
- 각 페이지를 저장하고 해당 페이지 조건을 통과한 뒤에만 다음 페이지 진행
- 각 non-trivial 페이지를 그리기 전에 owner가 요구하는 text-fit page-object 검사를 실행
- `spec_lock.md` 재독 cadence와 page rhythm을 checkout 계약대로 준수
- 각 페이지 완료 직후 `executor/page_complete --page N` 기록
- 실제 QC 호출마다 `qc/start`와 `qc/result` 기록
- `qc/start`에는 page를 붙이지 않고, page-scoped 결과일 때만 `qc/result --page N` 사용
- 오류는 모두 수정하고 재검증하며, 실제 SVG 재작성 페이지마다 rewrite를 1 증가

P01 gate, 모든 milestone incremental gate, 마지막 full-project QC를 수행하고 error 0을 요구한다. text-geometry warning은 owner 규칙대로 각각 처분한다. owner가 자동 요구하는 선택적 pixel check 대상이 있으면 live preview URL로 실행하고 직접 확인한다. 완료 후 telemetry `executor/complete --outcome ok`를 기록한다.

노트와 self-contained SVG preview 요청이 없으므로 owner에 따라 postprocess/finalize를 생략하고 `postprocess/start --outcome skipped`, `postprocess/complete --outcome skipped`를 기록한다.

## 7. Export, verify, telemetry 종료

telemetry `export/start` 뒤 canonical `svg_to_pptx.py`를 별도 호출해 PPTX를 생성하고 성공하면 `export/complete --outcome ok`를 기록한다. telemetry `verify/start` 뒤 canonical `verify_deck.py <project> --no-render`를 실행하고 exit 0일 때만 `verify/complete --outcome pass`를 기록한다.

그 다음 정확히 한 번만 metrics snapshot을 기록한다.

- input bytes/tokens, file reads/duplicate reads, tool turns: host 계측이 없으면 `unavailable`
- svg output bytes: 실제 SVG 8개 크기 합
- svg pages: 실제 파일 수, 반드시 8
- rewrites: 실제 누적값

누락 계측을 0으로 쓰지 않는다. metrics 뒤 config observer로 telemetry end를 `outcome ok`, 동일 repo root/immutable fixture로 기록한다. 이어서 telemetry validate, `measure_run.py` 텍스트와 JSON 보고를 실행한다. 마지막으로 immutable fixture hash, payload canonical hash, HEAD, clean worktree, PPTX 존재, SVG 8개를 재검증한다.

사용자는 benchmark 격리를 위해 이 실행이 띄운 live preview를 모든 측정·검증이 끝난 뒤 종료하도록 명시적으로 요청했다. 해당 프로젝트의 canonical server `--shutdown`을 사용해 이 실행의 preview만 종료한다. 다른 PID를 종료하지 않는다.

실패가 발생하면 성공으로 꾸미지 말고, 가능하면 telemetry lifecycle을 `outcome error`로 닫고 정확한 blocker를 최종 보고한다.

## 8. 최종 보고

최종 답변에는 프로젝트/PPTX 절대경로, HEAD와 시작·종료 clean 상태, source/payload hash, telemetry validation과 measure 결과, stage durations, SVG 8개 파일명·byte·합계, 실제 Executor bootstrap 파일·byte·합계, rewrite 수, validate_spec/QC/export/verify 결과, 기존 산출물 무열람·무복사, preview 종료 여부, OS/server cache 미초기화 한계를 포함한다.
