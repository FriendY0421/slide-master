# 슬라이드 마스터 작업 개념과 FAH 담당방 인계

기준일: 2026-11-08 한국 시간. 사용자가 FAH 추가를 보류하고 다른 코덱스방에서
진행하기로 했다. 이 방에서는 FAH 개발·배포·접속 재시도를 하지 않는다.
이 문서는 인계 자료이며 운영 적용 승인이나 전체 기능 완료 증명이 아니다.

## 2. 서비스의 개념과 역할

슬라이드 마스터는 자료를 읽고, 사용자에게 내용을 확인받고, 편집 가능한 PPTX를
제작·검수·전달하는 전문 제작 흐름이다. Picker는 템플릿 선택 화면이며 PPT 제작기나
사용자 인증 서버가 아니다. FAH는 프로젝트의 권한·상태·실행을 연결하는 제어 계층이다.

FAH가 추가되더라도 기존 슬라이드 마스터 제작 경로와 검수기를 호출한다.
다른 PPT 엔진으로 교체하거나 FAH에서 별도의 유사 제작기를 다시 만들지 않는다.
FAH의 `ALLOW` 결과만으로 파일 소유권, 현재 구성안 승인, 모델 호출 권한을
확인했다고 간주하지 않는다.

## 3. 실제 사용자 작업 순서

1. 자료와 목적·장수·글꼴·크기·양식을 함께 확인한다. 회사 양식의 보존 영역도
   명시한다. 새로운 사진이나 문서가 오면 해당 자료의 사용 권한을 확인한다.
2. 기본형은 실제 등록된 템플릿 미리보기와 제작 방식을 선택한다. 카드 클릭은
   임시 선택이며, 템플릿 ID와 제작 방식 ID의 명시적 확정이 필요하다.
3. 사용자 정의형은 PPT·사진·스케치를 분석한다. 회사 사진은 원문·수치·레이아웃·색·
   글꼴 추정과 불확실성을 요약해 먼저 보여준다. DRM을 해제하거나 판독 불가 값을
   추측하지 않는다. 사진으로 원본 마스터나 숨은 수식을 복원했다고 주장하지 않는다.
4. 전체 장표안을 보여준다. 장표별 제목·핵심 메시지·주요 내용·배치와 시각 요소를
   포함하며 사용자가 추가·삭제·통합·재배열할 수 있어야 한다.
5. **현재 수정본**을 사용자가 승인한 뒤 제작한다. 템플릿 선택 확정은 제작 승인이
   아니다. 자료·내용·장수·양식이 바뀌면 기존 승인을 재사용하지 않는다.
6. 기존 경로에서 편집형 텍스트·표·병합 셀·도형·화살표·차트와 데이터 통합 문서를
   보존하거나 생성한다. 전체 장표를 배경 이미지 한 장으로 대체하지 않는다.
7. 최종 PPTX를 다시 열고 렌더링해 검수한다. 오류가 있으면 문구·열·행·여백·배치를
   우선 조정한다. 검사기 통과, 실제 화면 검수, 실제 PowerPoint 검수는 별도 기록한다.
8. 검수한 **동일 파일**을 비공개로 전달한다. 권한과 실제 다운로드 바이트를 확인하고,
   사용자의 정상 열림은 별도로 확인한다. 수정 후 파일이 바뀌면 이전 검수를 승계하지 않는다.

회사 자료의 지정 크기는 제목 14pt, 중제목·표 머리글 12pt, 표 본문 11pt,
주석 9pt, 표 안 최대 12pt다. 다른 템플릿의 전역 기본값으로 강제하지 않는다.
SamsungOneKorean을 요구한 자료에서 조용히 다른 글꼴로 바꾸지 않는다.
현재 검증에 사용한 Pretendard는 사용자가 승인한 임시 글꼴이다.

## 6. FAH 담당방에서 이어받을 과제 — 이 방에서는 보류

대상 저장소는 `FriendY0421/friendy-automation-hub`다. 마지막 읽기 기준은
`1722d098a5732355f0c9ddb8796ae8de5552e174`이며, 담당방에서 현재 HEAD와
FAH의 `AGENTS.md`·`AI_CONTEXT.md`·`AI_STATE.json`·읽기 순서를 다시 확인해야 한다.
이 방에서는 FAH 소스·운영·레지스트리·로그인·배포를 변경하지 않았다.

1. FAH 등록부와 격리 계약을 확인한다. 읽은 `PROJECT_ISOLATION_REGISTRY.json`과
   `FAH_UNIVERSAL_PROJECT_REGISTRY.json`에는 `SLIDE_MASTER` 항목이 없었다.
   이는 운영 Sheets Registry에 항목이 없다는 증거가 아니다. 서로 구분해 확인한다.
2. 기존 Owner 인증 경로를 재사용한다. 현재 소스는 MYSELF/USER_DEPLOYING 웹앱이며,
   `FAH_phase2StateSyncReadyAssertOwnerIdentity_`가 active/effective 사용자를 비교한다.
   `actor`, `ownerConfirmed` 같은 요청자 입력으로 인증을 대신하지 않는다.
3. 실제 첨부 수신·사용자와 파일 소유/이용권·MIME/크기/해시·현재 승인 자료를 연결한다.
   읽은 `Index.html`의 파일 입력은 GitHub 개인키 등록용이며 PPT 첨부 기능이 아니다.
   이 입력을 재사용하거나 인증정보를 자료 파일처럼 취급하지 않는다.
4. 실제 모델/작업 실행 계약을 확보한다. 읽은 FAH 모바일 요청 경로는 판단용 미리보기이며
   `executionAllowed=false`다. 연결된 PPT 분석·생성 worker가 확인되지 않았다.
   기존 ChatGPT/Codex 작업이 있다는 사실만으로 FAH에서 호출 가능하다고 가정하지 않는다.
5. 기존 `.fah/execution-contract.json`은 v1이며 템플릿 필드 중심이다.
   제작 방식·현재 구성안·입력·사용자·검수 파일 결합은 추가 확인이 필요하다.
   FAH `ALLOW`를 로컬 제작 가드의 우회 수단으로 사용하지 않는다.
6. PPTX의 비공개 저장·다운로드를 연결한다. 기존 Drive JSON 상태 파일 전달은
   PPTX 전달 경로가 아니다. 동일 최종 바이트·권한·실제 수신자 정상 열림까지 검증한다.
7. 대상·변경·영향·기존 권한 사용 범위·비용·검증·중지·복구를 묶어 운영 적용안을 만든다.
   이 인계 문서가 새 권한·설치·결제·운영 배포·병합 승인은 아니다.

작성 도중 보류된 파일 검증기 초안은 로컬 비공개 검토 폴더에 보존했다.
미검증·미적용이며 공개 소스나 설치된 플러그인 기능에 포함되지 않는다.
FAH 담당방은 해당 초안의 존재를 구현 완료 증거로 사용하지 않는다.

## 7. 환경·파일 복구와 남은 외부 조건

- PC가 켜져 있으면 로컬 우선이다. 환경이 바뀌면 현재 파일·버전·공간·쓰기·기존 도구를
  확인한다. 클라우드 검증과 실제 아로 컴퓨터의 검증을 구분한다.
- 아로는 기존 권한으로 필요한 기초 파일을 복구한 뒤 별도 튜토리얼 없이 진행한다.
  다른 컴퓨터에는 대상·파일·다음 작업을 간단히 안내한 뒤 진행한다.
- [`RESET_RECOVERY_POLICY.md`](../RESET_RECOVERY_POLICY.md)의 Drive 복구 절차를 따른다.
  0.4.5 이름의 이전 기초 ZIP은 현재 0.4.7 설치본이 아니다. 기존 관리 캐시에 덮어쓰지 않는다.
- 현재 복구본은 원본 0.4.6·후보 0.4.7·0.4.6 내용을 0.4.8로 복원하는 묶음이며,
  비공개 Drive 실제 재다운로드·해시 검증을 마쳤다. 실제 회귀가 있을 때만 당시 최신
  릴리스 확인 후 승인된 복구를 적용한다. 과거 복구본은 삭제하지 않는다.
- 원래 Picker의 서버/터널과 Windows PowerPoint는 PC에 의존한다. PC를 끄면
  기존 Picker가 상시 사용된다고 안내하지 않는다. 실제 미리보기와 수동 확정 대체 경로는
  원래 App의 상시 호스팅과 구분한다.
- SamsungOneKorean의 로컬·서버·클라우드·임베딩 권리는 미확인이다. 등록·업로드·임베딩하지
  않는다. 회사 원본 PPTX도 없으므로 원본 마스터/보존 영역의 정확한 XML 비교는 조건부다.
- 지금 이미 확인된 다운로드·열림·Picker 선택을 사용자에게 반복 요청하지 않는다.
  새 자료의 내용 승인과 새 산출물의 수신 확인은 그 자료에 맞춰 별도로 받는다.
