# 실제 제작·검수·비공개 전달 — 호스트 실행 연결

이 지침은 기존 슬라이드 마스터의 승인 후 실행 경로다. 지침·앱 선언 자체는
서버나 OCR·모델 API가 아니다. 현재 대화 모델이 실제 원본 픽셀/내용을 읽고,
현재 호스트의 제공된 실행 환경과 이미 연결된 도구로 작업한다. 별도 모델
키·유료 서버·가짜 인증/첨부 ID를 만들지 않는다.

## 1. 입력과 승인 유지

- 이번 요청에서 사용자가 명시한 목적, 원본, 장수, 글꼴·크기, 수정/보존 영역,
  현재 확인한 구성안을 유지한다. 같은 선택을 다시 묻지 않는다.
- 실제 첨부는 호스트가 제공한 파일 참조와 소유/접근 범위를 사용한다. Drive
  파일은 승인된 커넥터의 metadata/readback과 원본 다운로드를 사용한다.
  공개 URL이나 로컬 경로를 실제 Cloud Work 사용자 첨부로 표시하지 않는다.
- 원문/수치/읽히지 않는 부분을 분리하고 모델이 실제 픽셀을 읽는다.
  예상 SVG/JSON을 이미지 분석 결과로 대신하지 않는다.
- 구성안의 현재 버전을 보여주고 실제 사용자 확인을 받은 뒤 제작한다.
  기록에는 실제 메시지/파일 참조만 사용한다. 확인 없는 새 구성은 생성하지 않는다.

## 2. 실행 환경과 기존 제작 소유자

- 실제 제공된 Presentations 스킬/런타임을 먼저 탐색한다. 해당 스킬과 현재
  소유자의 구현/최종화 지침을 읽고 사용한다. 호스트의 runtime path 조회 도구가
  있으면 그 결과를 사용하고, 없으면 제공된 runtime 정보만 사용한다.
- 회사 원본 PPTX를 채우거나 기존 native PPTX를 수정하는 경우 저장소의
  라우팅/해당 native 소유자를 재사용한다. 기존 SVG 프로젝트는 기존
  svg_to_pptx→verify_deck 소유자를 유지한다. #6, #10–#13 부품이 main에
  병합됐다고 가정하지 않는다. 새 변환기나 server dispatcher를 만들지 않는다.
- 사용자 확인을 받은 이미지 참조 재구성은 해당 호스트의 기존 Presentations
  native authoring/finalizer 경로로 실행할 수 있다. 원본 없는 도형/수치는 만들지
  않는다. 표·텍스트·도식은 native editable 객체로 만든다. 전체 이미지 한 장을
  붙여 편집 가능하다고 하지 않는다. 각 방법의 실제 사용 경로를 기록한다.
- 실행 도구가 없는 일반 채팅에서는 분석/구성안까지만 가능하다고 명시한다.
  로컬 PC 실행을 클라우드 실행으로 바꾸어 부르거나 파일 경로를 가짜 cloud
  다운로드로 만들지 않는다. 새로운 실행 환경이 필요하면 대상/영향/복구와
  권한·비용을 확인받고, 승인되지 않은 새 작업/설치를 만들지 않는다.

## 3. 회사 크기와 작은 영역 품질

- 사용자/템플릿 기준을 해당 작업에만 적용한다. 현재 회사 14/12/11/9pt와
  표 최대 12pt는 요청 시 기록하며 다른 템플릿의 전역 기본값이 아니다.
- 열 너비·행 높이·네 방향 여백·줄/문단 간격을 함께 조정하고 문구의 의미와
  수치를 보존한다. 임의 생략/글자 축소/잘림/겹침으로 통과시키지 않는다.
- 그림은 비율·원본 중요 영역·해상도를, 박스/도식은 배정 영역·선/색/정렬과
  화살표 방향을 확인한다. 사용자가 요구하지 않은 장식이나 제목을 추가하지 않는다.
- 요청한 실제 폰트 파일과 허용 범위를 확인한다. 조용한 대체·설치·임베딩 금지.
  권리 확인된 임시 폰트는 명시적으로 임시 검증으로 표시한다. 렌더 프로세스
  내부 폰트 등록과 Windows 폰트 설치는 구분한다. Samsung의 로컬/클라우드
  설치·서버 렌더·임베딩 권리가 미확인이면 사용하지 않는다.

## 4. 내보낸 파일 재열기와 검수

- 해당 소유자의 실제 finalizer/검증기로 새 파일을 최종화한다. 원본/복구본과
  실패 기록을 보존하고, 실패를 무시하거나 성공 코드로 강제하지 않는다.
- 내보낸 정확한 PPTX를 다시 import/open한 뒤 모든 장을 렌더하고 현재 모델이
  원본과 나란히 시각 검수한다. 줄바꿈/잘림/정렬/색상/수치/화살표/여백과
  native table/text/group/chart 편집성을 확인한다. 문제면 원본 소유자에서 수정,
  새 최종 파일로 내보내고 영향받은 장을 다시 검수한다.
- 동봉된 `scripts/dense_pptx_quality.py`와 `scripts/render_pptx_review.py/.mjs`는
  검토된 기존 #14 검사/렌더 부품이다. 승인된 실제 폰트 파일·SHA 및 작업별
  계약을 전달해 사용한다. 사용법은 각 script의 --help와 source docstring을
  따른다. 제공된 Python/Pillow, Node/Artifact Tool/skia runtime을 사용하고
  누락 패키지나 폰트를 자동 설치하지 않는다.
- 구조 검사(structure_only)는 폰트/한글 줄바꿈 검증을 대체하지 않는다.
  종료 0·페이지별 고유 번호/이미지·원본/PNG 해시 확인과 수동 화면 검수는
  별도로 기록한다. actual-font metric도 PowerPoint 렌더 인증은 아니다.
- PowerPoint가 실제 가능한 환경이면 별도로 열어 확인한다. native 객체 인식,
  실제 편집/저장/재열기, 정확한 폰트 표시 각각의 확인 여부를 구분한다.
  열기만 확인하고 편집/저장까지 통과했다고 하지 않는다.

## 5. 비공개 파일 전달 — 실제 도구 호출 필수

- 이 플러그인의 앱 매핑은 기존 Google Drive와 Picker를 참조한다. 새 OAuth
  범위나 사용자 권한을 부여하지 않는다. 현재 호스트에서 도구가 노출됐는지
  확인한다. Picker는 template 미리보기/선택용이며 제작/모델/파일 전달 API가 아니다.
- 전달 우선순위는 호스트의 실제 사용자 전용 산출물 다운로드 기능이다.
  사용자가 비공개 전달을 요청했고 기존 Drive 사용 권한이 있는 경우, 연결된
  Google Drive 스킬을 읽고 `upload_file`로 **실제 최종 PPTX 바이트**를 올린다.
  Office MIME 형식을 유지한다. 이미 지정한 폴더가 있으면 metadata로 확인하고
  그 폴더를 사용한다. 없으면 사용자의 My Drive에 새 파일로 생성한다.
- file_uri 입력 형식은 현재 도구 스키마대로 쓴다. 실제 로컬 절대 경로를 받는
  도구와 host file reference를 받는 도구를 구분한다. file_id/URL을 추측하거나
  다른 호스트의 경로를 있는 것처럼 전달하지 않는다.
- 업로드 후 `get_file_metadata`로 파일명·MIME·크기·권한을 읽는다. 반환된
  user owner/승인 수신자 외 anyone/domain 권한이 있으면 비공개라고 보고하지
  않는다. 권한 조회가 불완전하면 그 한계를 알리고 임의 share/delete를 하지 않는다.
- `fetch(download_raw_file=true, include_base64=false)` 등 실제 지원된 읽기
  도구로 정확한 최종 파일을 다시 내려받아 원본 SHA256과 비교한다. 지원이
  없으면 그 항목은 미검증이다. bearer/signed URL·자격정보는 공개하지 않는다.
- 성공 응답/readback에서 실제 반환된 지속 파일 링크만 사용자에게 준다.
  파일 접근 권한을 새로 넓히거나 공개 저장소에 올리지 않는다.
- 수령자의 직접 다운로드/열기는 사용자의 실제 확인이 있어야 완료다.
  assistant-side 왕복 해시 검사와 구분한다. GitHub에는 정제된 결과·해시만
  남기고 회사 자료/사진/폰트/비공개 URL/연결 ID는 넣지 않는다.

## 6. 완료와 중지

현재 사용자 목적에 필요한 제작·최종 검수·전달을 실제로 수행한다. 코드/지침
작성이나 연결 선언만으로 끝내지 않는다. capability가 부족하면 정확히 없는
기능, 시도한 공식 경로, 실행 가능한 대안과 최소 사용자 행동을 한 번에 알린다.
같은 실패/이미 통과한 검사를 진행 성과처럼 반복하지 않는다. 429/접근 실패는
새로운 근거 없이 반복하지 않는다. PC 기반 단계와 cloud 단계는 분리해 기록한다.
새 설치/권한/인증/비용/운영 배포가 필요하면 대상·변경·영향·보존·복구를
구체적으로 준비한 뒤 묶어 확인받는다. 새 플러그인으로 기존 대상을 대신하지 않는다.
